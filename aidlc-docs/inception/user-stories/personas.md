# Personas (knows-me)

> 스토리 범위는 MVP(요구사항 §5.1)에 한정. 제3자 소비자는 페르소나로 포함하되 **향후 대상**으로 표기하며 MVP 스토리는 없음.

## P1 — 소유자(Owner) 〔MVP 1차 사용자〕
- **정체**: knows-me를 자신의 기기에 설치해 쓰는 개인. 개발/업무 중 에이전트 세션·Notion·Gmail·파일을 남기는 지식 노동자.
- **목표**:
  - 매번 설명하지 않아도 "나"의 맥락(프로젝트 사정·일하는 방식)이 축적되기를.
  - 에이전트가 임의로 고른 것이 아니라, 내가 확인한 정확한 정보만 남기를.
  - 내가 없어도 나의 페르소나가 "나 대신" 초안을 써주기를.
- **동기/가치**: 반복 설명 제거, 정확성, 개인 데이터 통제.
- **불안/제약**:
  - 민감정보(메일·개인 파일)가 외부로 새는 것.
  - 인터뷰가 귀찮거나 강제되는 것 → **원할 때, 화면 전환 없이** 답하고 싶음.
  - 원본 로그가 그대로 쌓여 잡음이 되는 것.
- **기술 수준**: 높음(에이전트/CLI 사용). 로컬 앱·API에 익숙.
- **주 사용 인터페이스**: 대시보드, 인터뷰 Queue, 미니홈피/그래프 뷰, 페르소나 챗, 로컬 API.

## P2 — 제3자 소비자(Third-Party Consumer) 〔향후 대상 — MVP 스토리 없음〕
- **정체**: 소유자의 허락을 받아 소유자의 페르소나 API/아바타를 소비하는 외부 사람 또는 에이전트(팀원, 협업 에이전트 등).
- **목표(향후)**: 소유자가 부재해도 소유자의 맥락에 근거해 답을 얻거나 일을 진행.
- **MVP 상태**: 페르소나 API는 MVP에서 **로컬 전용·외부 노출 없음**(요구사항 D7). 따라서 이 페르소나 대상 MVP 스토리는 작성하지 않음. 원격 노출·인증(API 키/스코프)은 향후 확장.

---

## 시스템 액터(참고 — 페르소나 아님)
스토리 서술에 등장하지만 사용자 페르소나는 아닌 자동 주체:
- **수집 에이전트(Ingestion Agent)**: 소스에서 데이터를 가져와 가공·마스킹하고 Queue 아이템을 생성하는 백그라운드 로직.
- **페르소나 아바타(Persona Avatar)**: 소유자의 맥락으로 응대하는 대화 주체(챗 UI/로컬 API 뒤).

## 페르소나 ↔ 스토리 매핑 요약
- **P1 소유자**: 모든 MVP Epic(E1~E7)의 스토리 대상.
- **P2 제3자 소비자**: MVP 스토리 없음(향후). E6 페르소나 챗은 MVP에선 소유자가 소비.
