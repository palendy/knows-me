# knows-me

**새 Claude 세션을 열었을 때 Claude가 나를 이미 알고 있게 한다.**

## 문제

Claude Code는 프로젝트마다 메모리를 따로 둔다. 폴더를 옮기면 나를 모른다. 매 세션 같은 것을 다시 설명한다 — 리포 위치, 기동 방법, 테스트 명령, 작업 규칙, 시크릿이 어디 있는지.

## 이것은 무엇인가

내 활동 소스(지금은 Claude Code 세션, 앞으로 확장)에서 나에 대한 데이터를 모아 **정돈된 맥락 DB**를 만드는 시스템.

**에이전트 메모리와 다른 점**

- 메모리는 에이전트가 자기 판단으로 비정형으로 쓴다. 좋은 경험과 나쁜 경험이 섞인다.
- 여기서는 에이전트가 **후보만 고른다.** 후보는 **Queue**에 들어간다.
- Queue 항목은 사실만이 아니다. 에이전트가 나에 대해 궁금한 것, 맥락이 더 필요한 것을 **질문**으로 넣을 수 있다.
- 나는 시간 날 때 Queue를 보고 답한다. 답한 것만 맥락 DB에 들어간다.

## 목표

세션을 열면 Claude가 두 가지를 설명 없이 안다.

1. **이 폴더의 프로젝트 사정** — 리포, 기동, 테스트, 규칙, 시크릿 위치
2. **나의 일하는 방식** — 언어, 선호, 금지 사항

## 구성

```
활동 소스 ──▶ 후보 추출 ──▶ Queue ──▶ 내가 확인 ──▶ 맥락 DB ──▶ Claude가 읽음
(세션 87개)   (에이전트)   (사실·질문)  (일괄, 이후 1문)  (~/.claude/me/)  (CLAUDE.md · CLAUDE.local.md)
```

- 저장은 `~/.claude/me/`. 마크다운 파일 하나 = 사실 하나. git에 올리지 않는다.
- 사실마다 출처 세션, 확인 여부, 회사/개인 구분, 확인일이 붙는다.
- 시크릿 값은 격리된 암호화 파일에 둔다. Claude는 그 파일을 읽을 수 없다.
- Claude가 읽는 길은 둘: `~/.claude/CLAUDE.md`(일하는 방식) + 프로젝트 폴더의 `CLAUDE.local.md`(프로젝트 사정).

## 성공 기준

아무 프로젝트 폴더에서 새 세션을 열고 "이거 어떻게 띄워? 규칙은?"을 물으면 설명 없이 답한다.

## 활용 방향 (다음 단계)

- AI-DLC의 `team.md` · `project.md`를 이 DB에서 채운다 → practices-discovery가 다시 묻지 않는다
- Agent Factory 아바타 카드의 개인 실행 프로필을 이 DB에서 만든다
- 사람마다 쌓인 맥락 DB가 모이면 팀 맥락이 된다

## 이 리포에 있는 것

| 경로 | 내용 |
|---|---|
| `docs/requirements.md` | 요구사항 (grill-me 인터뷰로 확정) |
| `docs/me-ontology-review.md` | 사전 검토 — AI native 도입에서 메모리의 위치, 업계 조사 |
| `docs/aidlc-workflows.md` · `docs/aidlc-explained.md` | AWS AI-DLC 분석 |
| `docs/avatar-x-aidlc.md` | 아바타 카드 × AI-DLC 검토 |
| `docs/bedrock-setup.md` · `scripts/` | Claude Code ↔ Bedrock 연결 (해커톤 환경) |

맥락 DB 자체(`~/.claude/me/`)는 이 리포에 없다. 여기에는 도구·문서·시연만 둔다.
