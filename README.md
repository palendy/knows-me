# knows-me

**세션만 썼을 뿐인데 나에 대한 정보가 남았다. 그걸 의도적으로, 더 상세하게 남긴다.**

## 시작점

Claude Code와 Codex를 쓰면서 세션만 진행했을 뿐인데, 에이전트에 나에 대한 정보가 남아 있었다. Codex의 메모리 기능도 같은 일을 한다.

그런데 남는 것은 에이전트가 알아서 고른 것이다.

그래서 그 정보를 **더 상세하게, 의도적으로** 남기면 어떨지 해보는 것이 이 과제다.

## 챌린지

> **어떻게 나에게 반복 가능하고 필요한 정보만 잘 데이터베이스화할까.**

네 가지를 동시에 풀어야 한다.

| 문제 | 내용 |
|---|---|
| **반복 가능한 것 고르기** | 세션에는 일회성 대화가 대부분이다. 다음에도 또 쓰일 것만 골라야 한다 |
| **필요한 것만 남기기** | 에이전트가 자기 판단으로 모으면 좋은 것과 잡음이 섞인다 |
| **가공해서 넣기** | 원본을 그대로 쌓으면 메모리가 아니라 로그다. 요약·분류를 거쳐야 한다 |
| **여러 소스를 하나로** | 세션, 외부 시스템, 내 대답이 같은 형식으로 들어와야 한다 |

## 무엇을 모으나

세 가지 소스가 있다. 세션만으로는 나를 다 설명할 수 없다.

| # | 소스 | 어떻게 | 여기서만 나오는 것 |
|---|---|---|---|
| ① | **에이전트 세션** — Claude Code, Codex | 자동 수집 | 실제로 쓴 명령, 고친 것, 결정한 것 |
| ② | **외부 시스템** — Confluence, Jira 등 | 훅으로 자동 수집 | 내가 맡은 이슈, 팀 문서, 업무 흐름 |
| ③ | **인터뷰** — 에이전트가 나에게 물어봄 | 대화 | 세션에 안 나오는 업무 맥락, 하고 싶은 것 |

③이 중요하다. 코딩 세션만 봐서는 "VoC를 어떻게 처리하는지", "무엇을 자동화하고 싶은지"를 알 수 없다. 물어봐야 나온다.

## 인터뷰 — 확인이 아니라 캐내기

인터뷰에는 두 층위가 있다.

**확인형** — 세션에서 뽑은 후보가 맞는지 짧게 묻는다.
> "이 프로젝트는 `./run.sh`로 띄우는 것 맞나요?"

**심화형** — 수집된 정보에서 가설을 세우고, 거기서부터 파고든다. 답에서 나온 단어를 다시 파고든다.
> 관찰: 세션 절반이 SLSI 에이전트 리포다
> → "SLSI 에이전트 개발하시는 것 같은데, 자동화하고 싶은 업무 있으세요?"
> → (답에 'VoC'가 나옴) "VoC는 지금 어떻게 처리하고 계세요?"
> → "그중 반복되는 건 어떤 건가요?"

한 번에 하나씩, 답을 근거로 다음 질문을 만든다. 이렇게 해야 세션에 없는 업무 맥락이 데이터가 된다.

## 방법

에이전트는 **후보만 고른다.** 후보는 **Queue**에 들어간다. 내가 확인한 것만 맥락 DB에 들어간다.

Queue 항목은 두 종류다.

- **사실 후보** — "이 프로젝트는 `./run.sh`로 띄우죠?"
- **질문** — 에이전트가 나에 대해 궁금한 것, 맥락이 더 필요한 것

나는 시간 날 때 Queue를 보고 답한다. 처음 한 번은 목록을 일괄로, 이후는 세션이 끝날 때마다 하나씩.

## 목표

세션을 열면 Claude가 두 가지를 설명 없이 안다.

1. **이 폴더의 프로젝트 사정** — 리포, 기동, 테스트, 작업 규칙
2. **나의 일하는 방식** — 언어, 선호, 금지 사항, 맡은 업무

## 구성

```
① 에이전트 세션 ─┐
② 외부 시스템   ─┼─▶ 가공 ─────▶ Queue ─────▶ 내가 확인 ─▶ 맥락 DB ─▶ Claude가 읽음
③ 인터뷰        ─┘   요약·분류   사실후보·질문   일괄→1문    ~/.claude/me/   CLAUDE.md
                                      ▲                          │      CLAUDE.local.md
                                      └──── 다음 질문 생성 ◀──────┘
```

- ①은 지금 만든다. ②는 붙일 수 있는 구조로 만들고 하나를 붙여 본다. ③은 ①·②가 쌓일수록 좋아진다.
- **가공**: 원본을 그대로 넣지 않는다. 반복되는 것만 골라 요약하고 분류한 뒤 Queue에 넣는다.
- 저장은 `~/.claude/me/`. 마크다운 파일 하나 = 사실 하나. git에 올리지 않는다.
- 사실마다 출처(어느 소스·언제), 확인 여부, 회사/개인 구분, 확인일이 붙는다.
- Claude가 읽는 길은 둘: `~/.claude/CLAUDE.md`(일하는 방식) + 프로젝트 폴더의 `CLAUDE.local.md`(프로젝트 사정).

## 성공 기준

아무 프로젝트 폴더에서 새 세션을 열고 "이거 어떻게 띄워? 규칙은?"을 물으면 설명 없이 답한다.

## 활용 방향 (다음 단계)

- AI-DLC의 `team.md` · `project.md`를 이 DB에서 채운다 → practices-discovery가 다시 묻지 않는다
- Agent Factory 아바타 카드의 개인 실행 프로필을 이 DB에서 만든다
- 사람마다 쌓인 맥락 DB가 모이면 팀 맥락이 된다

맥락 DB 자체(`~/.claude/me/`)는 이 리포에 없다. 여기에는 도구·문서·시연만 둔다.
