# knows-me 요구사항 정의서

## 1. 프로젝트 개요

### 1.1 서비스 비전
에이전트 세션·외부 시스템·파일 등 흩어진 나의 흔적을 자동으로 모으고, 인터뷰로 보충·구체화하여,
"나"를 정확히 아는 구조화된 개인 맥락 데이터베이스를 만든다. 그리고 그 맥락을 여러 인터페이스로 제공한다.

### 1.2 핵심 가치 제안
- **나의 관점**: 기존 에이전트 메모리와 달리, 내가 선호하는 정보를 내가 원하는 형태로 정확히 보유한다.
  (에이전트가 임의로 고른 것이 아니라, 반복 가능하고 필요한 것만 확인을 거쳐 남는다.)
- **활용 관점**: 내가 자리에 없어도, 나의 맥락을 아는 에이전트/아바타가 팀에서 나의 일처리를 대신할 수 있다.

### 1.3 사용자
- 현재: 나 혼자 사용하는 개인 도구.
- 확장(추후): 내가 권한을 부여한 사용자도 나의 맥락(또는 일부)에 접근·활용할 수 있어야 한다.
  → 데이터 모델과 권한 구조는 처음부터 다중 사용자로 확장 가능하게 설계한다.

## 2. 서비스 구성

### 2.1 주요 구성 요소
- **데스크탑 앱 (Tauri)**: 수집·가공·인터뷰·조회·대화의 중심. 로컬 실행.
- **로컬 저장소 (암호화)**: 원본이 아닌 가공된 맥락 데이터를 구조화하여 저장. 클라우드 미사용.
- **소스 커넥터**: 에이전트 세션 / 외부 시스템(API) / 파일(폴더 감시·수동 업로드)에서 데이터를 가져온다.
- **가공·인터뷰 엔진**: 수집 원본을 요약·분류하고, 불확실한 것은 Queue에 질문/사실 후보로 적재.
- **LLM**: 요약·분류·인터뷰·페르소나 대화. 이미지 입력(비전 인식)을 지원한다고 가정.
- **제공 인터페이스**: 대시보드 / 미니홈피 뷰 / 지식 그래프 / 페르소나 챗 UI / REST API.

## 3. 핵심 기능 요구사항

### 3.1 소스 수집 (Data Ingestion)

#### 3.1.1 에이전트 세션 수집
목적: 실제로 쓴 명령·고친 것·결정한 것을 자동으로 확보한다.
기능 요구사항:
- 대상: Claude Code, Codex 세션 기록.
- 방식: 로컬 세션/트랜스크립트 저장 위치를 읽어 자동 수집.
- 주기: 세션 종료 시점 또는 주기적 배치로 신규분만 증분 수집.
- MVP 우선순위: **소스 중 1순위**로 이 소스부터 구현한다.
- (경로·수집 트리거 세부는 §부록 B 참조 — 확정 필요)

#### 3.1.2 외부 시스템 수집 (API 우선)
목적: 세션에 안 나오는 업무 산출물(이슈·문서·메일)을 확보한다.
기능 요구사항:
- 대상: Confluence, Jira, Notion, Gmail.
- 방식: 각 시스템의 공식 API 연동을 우선한다(OAuth/토큰 기반).
- 수집 범위: 원칙적으로 "내 것"만 (내가 담당한 이슈, 내가 작성/수신한 문서·메일 등)으로 필터.
- 주기: 주기적 동기화(증분).
- 자격증명은 암호화 보관(§3.5).

#### 3.1.3 파일 수집
목적: 사진·문서 등 파일 형태의 맥락을 확보한다.
기능 요구사항:
- 대상: 사진(이미지), 텍스트 파일, 오피스 파일.
- 방식(우선): 시스템별로 잘 알려진 폴더(예: 다운로드, 문서, 스크린샷 폴더)를 **감시**하여 자동 수집.
- 방식(보조): 앱에서 **수동 업로드** 기능 제공.
- 이미지 처리: LLM 비전 인식으로 이미지 내용을 텍스트 맥락으로 추출(가정).
- 오피스/텍스트: 본문 파싱 후 요약·분류 대상으로 투입.

#### 3.1.4 (향후) 카카오톡 대화
- 이번 범위에서는 수집 방식 미확정(보류). §5 향후 확장 참조.

### 3.2 데이터 가공 및 Knowledge DB

#### 3.2.1 가공 (Processing)
목적: 로그가 아니라 "맥락"으로 만든다.
기능 요구사항:
- 원본을 그대로 쌓지 않는다. 반복되는 것/필요한 것만 골라 요약·분류.
- 일회성·잡음은 걸러낸다.
- 불확실하거나 더 알아야 할 것은 인터뷰 Queue(§3.3)로 넘긴다.

#### 3.2.2 저장 및 메타데이터
목적: 조회 가능하고 신뢰할 수 있는 구조화 저장.
기능 요구사항:
- 저장 단위: "사실(fact)" 단위 레코드.
- 각 사실 메타데이터(유지):
  - 출처(어느 소스 · 언제 수집)
  - 확인 여부(확인/미확인)
  - 회사/개인 구분
  - 확인일
- 중복/충돌: 같은 사실이 갱신되면 덮어쓰지 않고 **이력을 남긴다**(변경 이력 추적).
- 저장 구조(그래프 DB vs 레코드): 지식 그래프를 목표로 하되, 구체 스키마는 구현하며 점진적으로 고도화한다(§부록 B).

### 3.3 인터뷰 Queue

#### 3.3.1 Queue 아이템 생성
목적: 확인되지 않은 것/더 알면 좋은 것을 쌓아둔다.
기능 요구사항:
- 수집·가공 과정에서 에이전트가 자동으로 아이템을 생성.
- 아이템 종류(둘 다 지원):
  - **사실 후보(확인형)**: 세션 등에서 뽑은 사실이 맞는지 짧게 확인. 예) "이 프로젝트는 `./run.sh`로 띄우죠?"
  - **질문(심화형)**: 수집 정보에서 가설을 세워 파고드는 질문. 답에서 나온 단어로 다음 질문을 이어감.
- 우선순위/만료 관리: 아이템에 우선순위가 있고, 오래되었거나 반복되는 질문은 정리(만료/억제)한다.

#### 3.3.2 답변 (인터뷰 UX)
목적: 부담 없이, 원할 때, 흐름 끊김 없이 맥락을 채운다.
기능 요구사항:
- 사용자가 **원할 때** 답한다(강제 없음).
- 각 아이템에 **답변 선택지를 제시**하고, **직접 입력**도 가능해야 한다.
- 앱의 **Queue 화면 안에서 화면 전환 없이** 답변이 이뤄져야 한다.
- 확인/답변된 아이템만 Knowledge DB에 반영. 답변은 새 질문 생성의 근거가 될 수 있다.

### 3.4 제공 인터페이스 및 활용

#### 3.4.1 대시보드 (데스크탑 앱)
- 수집 현황, 대기 중인 Queue 개수, 최근 확정된 사실 등 상태를 한눈에 표시.

#### 3.4.2 미니홈피("싸이월드") 뷰
- 수집·확정된 나의 맥락을 미니홈피 스타일로 시각화하여 "나"를 한 화면에 보여주는 뷰.

#### 3.4.3 지식 그래프 뷰
- Knowledge DB를 노드/관계 그래프로 탐색.

#### 3.4.4 페르소나 아바타 대화 (Chat UI)
- 나의 맥락을 기반으로 페르소나를 가진 아바타와 대화하는 인터페이스.
- 소비자: **나 또는 타인**.
- (참고: 기존 "Web Share View"는 이 페르소나 대화 인터페이스로 재정의)

#### 3.4.5 REST API
- 소비자: **제3자(외부 에이전트/서비스)**.
- 제공 기능(페르소나 활용 — **최우선 순위**):
  - 나 대신 네트워킹(메일/메신저/DSDN 게시글 작성 등)
  - (심화) 나 대신 회의 참석(회의 내용 이해, 나의 페르소나로 응대)

### 3.5 보안
목적: 개인·민감 데이터를 로컬에서 안전하게 보관.
기능 요구사항:
- 저장 위치: **로컬 전용**(클라우드 미사용).
- 저장 데이터 **암호화** 필수(맥락 데이터 및 외부 시스템 자격증명 포함).
- **최초 설치 시 비밀번호 설정** → 이 비밀번호를 기반으로 키를 만들어 데이터 암호화.
  (비대칭 암호화 적용 검토 — 세부 키 관리 방식은 §부록 B)
- 외부 시스템 자격증명(토큰/OAuth)은 암호화하여 보관.
- 권한 확장(추후): 부여된 사용자만 접근할 수 있도록 접근 제어를 설계에 반영.

## 4. MVP 개발 범위
- **범위: 위 3장의 기능 전부를 MVP로 구현한다.**
- 단, 소스 수집은 **에이전트 세션(§3.1.1)부터** 붙이고 외부 시스템·파일을 순차 확장.
- 포함:
  - 소스 수집(에이전트 세션 → 외부 시스템 → 파일, 이미지 비전 인식 포함)
  - 가공 및 Knowledge DB(메타데이터·변경 이력)
  - 인터뷰 Queue(확인형+심화형, 선택지+직접입력, 전환 없는 UX, 우선순위/만료)
  - 인터페이스(대시보드, 미니홈피 뷰, 지식 그래프, 페르소나 챗 UI, REST API)
  - 보안(로컬·암호화·설치 시 비밀번호)
- 기술 스택: 데스크탑 앱은 **Tauri**.

## 5. 향후 확장
- 권한 기반 다중 사용자(부여된 사용자의 접근·활용).
- 카카오톡 대화 수집.
- 개인별 맥락 DB가 모이면 팀 맥락으로 확장.

## 부록 A. 용어 정의
- **소스(Source)**: 나의 데이터를 얻는 출처. 에이전트 세션 / 외부 시스템 / 파일 등.
- **사실(Fact)**: Knowledge DB에 저장되는 확인된 맥락의 최소 단위.
- **인터뷰 Queue**: 확인이 필요하거나 더 알아야 할 항목(사실 후보·질문)을 쌓아두는 대기열.
- **확인형/심화형**: 확인형은 후보 사실의 진위를 짧게 확인, 심화형은 가설을 세워 파고드는 질문.
- **페르소나 아바타**: 나의 맥락을 학습해 나처럼 응대하는 대화 주체.
- **MVP**: Minimum Viable Product(최소 기능 제품).
